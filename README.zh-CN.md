# 记忆旧时光 · jiyijiushiguang

**一套在 Windows 上跑多台 DeepSeek Harness（DSH）的工具与方法：跨机传消息、共享记忆库、守卫规则、
以及"改坏了怎么救回来"的剧本。**

> 为什么做这个：上下文过长一直是 DSH 使用中的痛点，而多台机器之间的协作也还没有成熟范式。
> 我们的做法是把记忆放到外部数据库里、用通信桥把几台机器串起来，并给每一步都加上"可验证、可回滚"。

**状态：施工中。** 代码与教程计划在 **2026-10-25/26（周末）** 完成。
现在还不能直接用，仓库还在搭建 —— 可以先关注，或者在 Issues 里说你想看哪部分。

## 将来包含什么

| 目录 | 内容 | 适合谁 |
|---|---|---|
| `bridge/` | 通信桥：DSH 插件（收）+ 投递器（发）+ 看门狗 | 两台及以上机器都跑 DSH 的人 |
| `guard/` | 守卫：兜底规则、验证落实、安装复核、回滚机制 | 让 AI 管着一堆脚本的人 |
| `rescue/` | DSH 故障自诊与回滚；含用 WinRM 远程读 DSH 日志取证 | 改坏过 DSH 的人 |
| `memory-guide/` | **纯教程**：自己装 SQL Server、表结构、规则库方法论、同步与检索、handoff | 被上下文长度困扰的人 |

**绝不含数据。** 本仓库只有代码、模板和文档，不含任何人的记忆、凭证、主机名或日志。
配置示例一律用占位符（`HOST-A`、`10.0.0.x`、`<PAIR-TOKEN-A-B>`、`<DSH_HOME>`）。

## 五条设计原则（都是踩出来的）

1. **只监听回环。** 收件端绑定 `127.0.0.1`；每对机器一把令牌，不经过任何云端中转。
2. **端口自发现。** DSH 每次启动会换随机端口，所有客户端都要自己发现，而不是写死。
3. **改前备份、改后验证。** 动过的文件旁边都留 `.bak-before-<原因>-<时间戳>`。
4. **一次只改一处。** 同时改两处，出问题就无法二分定位。
5. **秘密不进聊天、不进日志、不进命令行。** 放密码库，用文件或剪贴板传递。
