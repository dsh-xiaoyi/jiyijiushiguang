## 0. 一句话目标

```
不是做一个"能注入点东西"的插件，而是做一个**有契约的记忆层**：
  写入有规则、存储有版本、检索有理由、注入有预算、丢弃有记录、坏了能自愈。
```

## 2. v2 的五层架构（提案）

```
① 写入层（Ingest）
   规则：什么值得记（决策/事实/规则/更正/任务闭环/踩坑）｜什么不记（寒暄/重复/临时）
   机制：抽取 → 去重（指纹）→ 合并（同主题演进成一条带版本）→ 落 kind 分类
   关键：写入时就要能回答"这条取代了哪条旧记忆"

② 存储层（Store，即 dbo.memories）
   新增字段：fp(指纹) ｜ ver(版本) ｜ supersedes(取代谁) ｜ ttl/decay_class ｜ last_used_at ｜ used_count
   唯一性：fp 唯一（防重复）；同 supersedes 链成"事实的演化史"
   保留：append-only 审计（谁在何时写入/取代）

③ 检索层（Retrieve）
   三段式：关键词(IDF) → 语义(可选 embedding，本地缓存) → 重排（时间衰减 + 使用频率 + 命中强度）
   必须可解释：每条注入带"为什么被选中"（命中词/相似度/最近使用）

④ 注入层（Inject，契约化）
   预算：总上限（如 12000 字符）分四块：核心约定 / 分片 / 定义型记忆 / 相关记忆+活动
   每块独立上限，**超限列出未注入条目**（不允许静默 slice）
   分片：conventions.d 按话题命中（已上线）
   回执：每次注入写 inject.log（块名/字符数/条目 ID/丢弃原因）

⑤ 自愈层（Self-heal）
   副本过期 → 注入里显式告警（"副本 X 分钟前，可能不是最新"）
   库不可达 → 降级但不静默（标题写"离线副本模式"）
   插件自检任务：每日跑一次"注入契约体检"（上限/分片/回执/副本新鲜度）
```

## 3. 注入契约（v2 核心，先定这个再谈别的）

| 块 | 来源 | 建议上限 | 超限行为 |
|---|---|---|---|
| A 核心约定 | conventions.md | 8000 字符 | 列出未注入章节 |
| B 约定分片 | conventions.d/*.md（话题命中） | 每片 ≤1500，最多 3 片 | 列出未注入分片名 |
| C 定义型记忆 | memories(kind=decision/fact/rule/correction) | 6 条 × ≤160 字符 | 列出被省略的 ID |
| D 相关记忆 | AUTO-RECALL 命中 | 4 条 × ≤200 字符 | 标注"还有 N 条相关，可 search" |
| E 活动/时间线 | 各机 last_seen | 6 行 | 省略最旧 |
| 合计 | — | 12000 字符 | 逐块降级，**绝不整段切** |

## 8. 实施结果（2026-10-24 当晚，A → B → C1-C3 全部落地并验证）

### 8.1 注入契约（已上线，有回执）

```
inject.log 每轮的 INJECT-BUDGET（21:09 实测）：
  recall 775 ｜ conv 2022 ｜ shards 1251 ｜ pinned 1193（掉 1 条）｜
  recent 1059 ｜ activity 206 ｜ hints 281 ｜ dup 5
分段预算：conv 8000 / shards 2600 / recall 1600 / pinned 1200 / recent 2000 / activity 700 / hints 400
总上限 maxChars 16000（conventionsMax 8000）
超限行为：追加"…（本段超出预算，省略 N 条；用 search/recent 取更多）"——绝不静默 slice
```

### 8.2 分片（按话题命中）

```
conventions.d 分片：首行 [关键词 …]；按命中关键词数排序，最多注入 3 片（config.shardCap）
未命中或超上限的分片合并成一行清单（相当于目录），不占预算
实测：贴话题时注入 2 片 + 列 3 片。
```

### 8.3 记忆状态与审计（C1/C2，已建表）

```
dbo.memories 新列：valid_from / valid_to / status / revision / replaced_by / importance / access_count / last_injected_at
dbo.memory_events：append-only（add / merge / supersede / retire / reject / inject）
dbo.memory_links：supersedes / duplicates / refines / derived_from / evidence_of
引擎：save 后自动写 action='add'（含 body SHA256）
示例（实测）：id=22958 建后 add 事件；随后 status='retired' + retire 事件 —— 这就是"删除=标记"的落地形态
```

### 8.4 捕获改"证据"（C3）

```
捕获写入 kind='evidence'（config.captureKind 覆盖）
注入端过滤：kind ∈ {checkpoint, evidence, llm-call} 与 status ∈ {retired, archived} 一律不进注入
代价/收益：recent 段字符从 1698 → 1059（少了一堆压缩摘要），但真正的结论条目更靠前
```
