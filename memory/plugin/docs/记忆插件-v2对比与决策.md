## 二、三方对照（现有 / 调研建议 / 审计缺陷）

| 主题 | 我们现在（v1.5） | 同类最佳实践（调研） | 审计发现的缺陷 | 结论 |
|---|---|---|---|---|
| 注入预算 | 单一 `maxChars=12000` + `conventionsMax=3000`，超了 `slice` | 分区预算（每段硬上限 + 超限整段省略 + 写回执） | 配置覆盖代码；真按 8000 填满必截"最近结论"；无回执 | **必须改** |
| 去重 | 无（定义型与最近结论高度重叠） | 注入前全局去重（seen 集合，优先级） | 同一会话两次注入结果完全不相交（话题源污染） | **必须改** |
| 检索 | 纯 IDF 关键词，短语不切词 | 关键词 + 向量 + 重排（Graphiti 做法） | 3 个可复现反例（`search 备份_` 440 条、`"共享盘 SMB"` 零命中、排序按 updated_at） | 必改（先修反例再谈向量） |
| 记忆状态 | 无状态列，新旧混杂 | 双时间 + status(current/superseded/archived)，删除=retired | checkpoint 占注入、且周维护按 `subject` 分区会误删 | **必须改** |
| 捕获 | 压缩摘要直接当记忆（截 6000） | 证据先落库，curator 异步蒸馏，受控写入 | 今天 28 条同会话；26 条下周会被删 | 必改（重） |
| 审计 | 只有 bridge.log 一行计数 | append-only memory_events + 工具面 | 写入无留痕，查不出谁重复写 | 值得做 |
| 自愈 | 副本缺失时才告警 | 过期显式告警 + 降级可见 | 42.7% replica tick 被 busy 跳过、最长 12 分钟空档 | 必改 |
| 硬删除 | 我们本来就不删 ✅ | —— | 周维护在删 checkpoint（自作主张） | **先停掉这个删除** |

**结论一句话**：现有方案不是"推倒重来"，而是**先把三处"静默"变成"可见/可见/可控"**（配置可见、失败可见、删除可控），再谈分片预算与状态列。

## 三、三个选项（可组合，按风险递增）

### 选项 A · 止血（推荐先做，约半天）

```
A1 配置对齐：cordis.patch.yml 里 conventionsMax 3000→8000、maxChars 12000→16000
   并把 check-conventions.ps1 改成读**生效配置**（而不是代码默认）→ 消灭假 PASS
A2 副本原子写：dsh-mem.ps1:1747 改 tmp+rename（同目录 .tmp → Move-Item -Force）
   插件侧：JSON.parse 失败不再置空，注入里写大字告警"副本读取失败 + 原因 + 副本路径/时间"
A3 停掉 checkpoint 的自动删：mem-maintenance.ps1 的删除分支改为"只出报告，不删"
A4 注入回执落地：确认 inject.log 生效（需一次重启），并把 INJECT-BUDGET 也写进去

回滚：A1/A3 改文件可逆；A2 保留旧行注释；A4 仅日志

### 选项 B · 结构（A 之后 1–2 天）

```
B1 分区预算 + 可见省略清单（约定/分片/定义型/recall/活动/结论 六段）
B2 注入前全局去重（seen 集合 + 末尾"去重 N 条"）
