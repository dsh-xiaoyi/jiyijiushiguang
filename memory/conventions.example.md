> 该文件由 `dsh-memory-bridge` 插件**完整注入**到每次会话的系统上下文。
> 只放"长期有效的硬约定"；过程细节放记忆库，不往这里堆。文件时间以 mtime 为唯一来源（不在正文里手写时间）。

## 1. 备份与删除（用户 2026-10-14 / 10-16 / 10-23 三次确认）

```
本地 E:\.backup 的加密包：
  · 超过 180 天 → 由 DSH 在**备份时**检查并提醒用户 → **用户确认后才删**；DSH 不要自己删
  · 不做独立的定时提醒任务（只在备份流程里查）
  · 本地平时不主动删（E 盘空间够）
冷备份（A:/B: 冷备盘）：同样 180 天 → 同样"备份时检查 + 提醒 + 用户确认"
云端（百度网盘）：空间大 → **长期保留**，不提醒、不删
打包用的明文暂存：**确认同步后立即删除**；E:\.dshbackup 只留「备份记录.txt」与「【说明】关于17的唤醒.txt」

备份流程：
  03:30 全库 .bak → <你的备份目录>\backup（示例：本地保留 30 天）
  周日 04:00 cloud-backup.ps1 打三段加密 7z（01-数据库与记忆 / 02-集群工具 / 03-脚本与手册）→ E:\.backup
        （含"过期检查"段：有超 180 天的才提醒）
  周日 05:30 包校验；密钥 → E:\iCloudDrive\DSH备份密钥-<同名>.txt（与包分开）；冷备 → A:/B:
三层：本地 + 云端 + 硬盘冷备份，一层不少
```

## 2. 通道职责

```
队列（dbo.agent_messages）= 可靠通道：任务/结果/回执/审计全走它（可重试、可离线补）
青鸟 exe（19387）= 实时通道：只发"现在就要"的短指令，发出后仍要落一条库记录
聊天注入要求目标会话活跃；空闲 ⇒ 502 / inactive context ⇒ **聊天不能当送达保证**
delivered_at 是"终态"，不是"成功"：成功 = delivered_at 非空 且 last_error 为空
一句话：**中枢可以丢，队列不能丢**
```

## 3. 重启与身份

```
改桥插件（index.mjs / cordis.patch.yml）⇒ 必须紧跟一次 DSH 重启（否则后续注入全失败）
重启"用户可见的 GUI"必须用**登录用户身份**；SYSTEM 任务起的是 session 0（看不见）
请避免用 SYSTEM 任务重启用户界面（会出现"进程在跑但界面看不见"的幽灵实例）
```

## 4. 判据纪律

```
一义：只判"出现了什么"（如出现了 inject failed），不判"缺少什么"（空闲 vs 故障无法区分）
有分母：误报率必须给"抽样 N 中 M"，0/0 就写"不可测"，不写 0%
不抖动：判据要扣掉不可避免的实时尾/采样相位
相位相关量（ACK 与信封时间差、探针间隔）**不得写成阈值或区间**
端口每次启动变化：**只发现，不持久化**（dsh-port.txt + /healthz）
"插件已加载" ≠ "能注入"；"清单说有" ≠ "机器上有"
```

## 5. 记忆优先（硬规则 · [RULE-DB-FIRST]）

```
回答任何涉及"以前/上次/之前/当时/约定/规则/决定/状态/进度/谁负责"的问题，
必须先查库再回答，禁止凭印象（硬规则，违反即返工）：
  1) 先查：原文检索（mem-find）/ 精确锚点（mem-anchors）或 dsh-mem.ps1 search|recent
  2) 命中必须引用证据：记忆 id 或 session+seq；查不到就说"查不到"并问用户，不许编
  3) 只有用户明确说"凭印象/先讨论"时才可跳过，且回答里必须注明"未查库"
  4) 原文回读：按 session+seq 取回原始消息，逐字校验，不用摘要顶替
查不到 ⇒ 视为不知道 ⇒ 问用户，不猜
做完决定 ⇒ 把最终版写回记忆，并注明取代了哪条旧记忆
```

## 6. 安全与权限

```
远控通道保留（向日葵=手机远控；内网另一条用于键盘失灵时关机重启）
  · 白名单按**指纹**（进程路径+服务名+端口+账号），不按名字
  · **不要清理 awesun_guard**（否则把人锁在外面）
DDL 只在 11 上用 sysadmin 执行（应用账号无 CREATE TABLE，是设计不是缺陷）
恢复类演练必须 sysadmin（sqlcmd -E）；应用账号只做读写
任何"删数据"的决定：**默认不删**，只提醒，决定权在用户
```

## 7. 硬边界

```
11 不做重计算；不可逆操作只在 17（VM，有快照/自动保存）上做
安全阀：CPU>85% / 空闲内存<2GB / 磁盘<10GB 时降级
证据纪律：PASS 必须有可复核数字；查不到 ≠ 没有；方法失败不能当证据
```

## 10. 对话逐字入库（硬规则 · [RULE-SYNC-NOW]）

```
每轮对话（用户消息 / 助手回复 / 工具调用与结果）产生后，必须立即、逐字同步进消息表：
  禁止等上下文压缩、禁止只存摘要、禁止截断；
  实时捕获（会话事件钩子）+ 定时兜底同步（例如每 3 分钟）双保险。
判据：
  · 系统活跃时，库里最新消息的时间与当前时间相差 ≤ 3 分钟
  · 24 小时内没有截断标记
  · 用 session+seq 回读原文，与当时逐字一致
缺失按"没做"处理并现场重建 —— 不要用"应该记过了"代替核对。
```
