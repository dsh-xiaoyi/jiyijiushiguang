# 复盘集（真实事故，脱敏）

> 每一条都写成"现象 → 根因 → 修法 → 防复发"。这是我们最想分享的部分：
> **一个框架的价值，往往由它踩过的坑决定。**

> 第一次读到这里，不必一次记住；先照着跑一遍，遇到问题再回来查对应那一节。
## 1. 幽灵实例：用 SYSTEM 重启用户界面

```
现象  远程重启后 DSH "起来了"，但界面上看不见，跨机也连不上
根因  用 SYSTEM 计划任务启动 GUI ⇒ 进程落在 session 0，用户桌面看不见
修法  改用"登录用户身份 + 交互式"任务启动；并约定：请避免用 SYSTEM 起用户界面
防复发 记录一条铁律 + 启动方式改为"交互式任务"（详见 docs/05）
```

## 2. 清单被截断，但检查"通过"了

```
现象  共享盘上的清单只有 2 行（原本 44 行），校验脚本仍然 PASS
根因  校验只比"清单自己声明的哈希"，没有"行数下限"断言
修法  加断言：契约行数 < 38 直接判 FAIL；并把契约搬进数据库
防复发 "清单说有" ≠ "机器上有" —— 双向比对：声明→实物、实物→声明
```

## 3. 旧口令触发账号锁定，连带共享盘掉线

```
现象  某台机器的共享盘突然 Access denied，提示账号被锁定
根因  保管库里存的是旧口令，多次重试导致账号锁定
修法  更新保管库；锁定后按流程解锁；共享访问用专用账号
防复发 口令变更必须同步保管库 + 用"失败一次就停"的策略，不要重试
```

## 4. 记忆系统的三层"看起来正常"

```
现象  会话一长就"忘记"之前定过的规则，反复被用户纠正
根因  ① 注入配置指向不存在的脚本（静默空注入）
      ② 只注入最新 8 条（旧约定永远进不来）
      ③ 有检索但没 IDF（常见词淹没稀有词）
修法  强制指令 + IDF 自动检索 + 关键约定全文 + 定义型记忆，四段按重要性排序
防复发 判据"插件已加载 ≠ 能注入"；用**行为证据**（注入内容里有没有新段落）验证重载
```

## 5. 备份的三种"我记得"

```
现象  连续三次把备份规则做错（目录、分层、删除时机）
根因  凭印象动手，没有先查"用户写过的说明文件"
修法  三查：对话记录 / 记忆库 / 目录里的说明文件；查不到就问，不猜
防复发 把"删除决定权在用户"写进关键约定，默认动作是不删
```

## 6. 自相矛盾的"红灯"

```
现象  规则"周包超过 8 天未更新"永远 FAIL，可实际包是当天打的
根因  这条检查同时要求"暂存目录里有 2 天内的 .bak"，而该暂存目录按规矩必须被删掉
修法  改判据：周包年龄 + 投放目录不含裸备份 + 暂存目录只留说明文件
防复发 不稳定的灯比红灯更糟：判据自相矛盾时会让人对告警疲劳
```

## 7. 假通过：方法失败被当成"没问题"

```
现象  某次探针"通过"，但代码其实没换
根因  用时间戳（ARMED 时间）判"是否加载"，时间戳常被旧值满足
修法  改判"行为差异"：新版本才有的输出/字段出现了，才算加载
防复发 证据要能区分"新行为"与"旧行为"，否则就是自欺
```
