# 记忆旧时光：设计

> 第一次读到这里，不必一次记住；先照着跑一遍，遇到问题再回来查对应那一节。
## 目标

会话一长就"忘记你们定过什么"——这不是模型记性问题，而是**机制缺失**：
旧约定没有被放到它眼前。

## 注入四段（每一轮都出现，按重要性排序）

| 顺序 | 段 | 作用 |
|---|---|---|
| 1 | **强制指令** | 回答"以前怎么定的"之前必须先查记忆库，不许凭印象 |
| 2 | **自动检索（IDF）** | 读最近的真实发言 → 提关键词 → 按稀有度加权 → 捞出相关旧记忆 |
| 3 | **关键约定全文** | `conventions.md` 每次完整注入（长期硬约定） |
| 4 | 定义型记忆 + 最近结论 | 决策/规则/事实/更正，不按新旧筛 |

> 顺序刻意如此：越靠前越不会被长度上限截断。

## 自动检索为什么要 IDF

第一版是"关键词等权 + 长度归一 + 阈值"，结果：

```
提问："你对 360 的防护能力怎么看"
  常见词：防护、能力 → 在几千条记忆里到处都有 ⇒ 分数被稀释
  稀有词：360      → 与常见词等权 ⇒ 没起到定位作用
  ⇒ 上周末刚做过的《360 演练报告》被阈值挡掉，答非所问
```

修法：**IDF（稀有词加权）** + 少量同义词扩展 + 门槛"分数≥1.2 且（中文命中≥2 或含数字标识）"。
修完之后同一句话，演练报告**排第一**。

## 三层缺陷的复盘（真实且值得抄）

```
① 注入永远是空的      —— 配置指向一个不存在的脚本，插件"加载成功"但什么都没注入
② 只注入最新 8 条     —— 库里有 1,500+ 条，8 条窗口只能看到"最近几小时"
③ 有检索但无 IDF      —— 常见词淹没稀有词，检索看起来在工作，却永远答不到点上
```

**共同点**：三层都不会报错。"看起来运行正常"的失忆最贵。

## 为什么"关键约定"要单独成文件

记忆库适合放"过程"，不适合放"必须永远成立的规则"。
把备份保留、删除决定权、重启身份这类**硬约定**单独放在一份小文件里、每次完整注入，
比"指望检索能召回到"可靠得多。

## 数据与隐私

- 会话/消息入库是为了"可追溯"，**不是**为了训练
- 本仓库不包含任何真实数据；示例一律占位
- 备份：本地 + 云端 + 冷备三层；删除类的动作**默认不删**，只提醒
