# 长期运行说明（能不能一直用、要注意什么）

> **先看这一句：目前只有 SQL Server 后端经过了长期运行验证。**
> MySQL 与 SQLite 后端**功能已经验收通过、现在就能用**，
> 但它们的"长期运行"（连续几周不人工干预）**还没有时间验证** —— 这是事实，不是保守。

## 一、成熟度分档

| 后端 | 功能验收 | 长期运行验证 | 依据 |
|---|---|---|---|
| **SQL Server** | ✅ | ✅ **已验证** | 生产环境连续使用数周（每日备份 / 注入 / 队列持续运行） |
| **MySQL 8.0.12 / 5.7.26** | ✅ 15 命令 + 独立断言 | ⚠️ **未做长期测试** | 2026-10-24 单日完整验收（建库 / 导入 267 行 / 幂等 / dump 10 表 6 触发器） |
| **SQLite 3.33+** | ✅ 15 命令 + 独立断言 | ⚠️ **未做长期测试** | 2026-10-24 单日完整验收（10 表 6 触发器 / 267 行 / 幂等 / .backup） |

一句话：**后两个后端"能用"和"久用"是两件事** —— 能用已验证，久用没有时间背书。

### 核心命令（三个后端都是这个状态）

```
save / search / recent / history / secrets / stats / roster / replica /
backup / sync / prune / handoff / recall   —— 全部验收通过
```

### ⚠️ 能用，但有前提

```
embed（语义检索）      未测。需要本地模型端点（bge-m3 等）。用前先跑：embed -Limit 5
MySQL 5.6.x           理论可用，未实测
MySQL 8.4+            认证插件默认改了（mysql_native_password 被禁用），按 docs/12 建账号
MariaDB               未实测
sync 的解压器          需要 Node 22.15+/23+；缺了会明确报错并 exit 1（v0.3.3 起）
SQLite 单文件          不能多机共享；并发写单写者；库文件即明文 → 必须收紧 ACL
每次命令都起一个客户端进程（约 50-100ms）→ 适合人用，不适合高频批量
```

### ❌ 不要用

```
v0.3.0 / v0.3.1    SQL Server / MySQL 配置启动即崩（release 正文里有警告）
v0.2.x 之前        没有 SQLite，也缺 5.7 / prune / 安全 相关修复
```

## 二、要把 MySQL 或 SQLite 当长期用，建议这样做

```
① 先在自己环境跑 1-2 周：每天看一次 backup / sync 的输出（数字对不对），别只看返回码
② 每周按 docs/15-verification-checklist.md 自查一次（machines 行数、去重、readback）
③ 锁版本：钉在 v0.3.3，不要跟着 main 走
④ 日志留档：把 backup / sync 输出保存下来，出问题时能对时间
⑤ 发现异常先停写、再备份、再排查 —— 数据比"服务在线"重要
```

## 三、长期运行的通用纪律

```
① 锁版本（同上）
② 定期自查（同上）
③ 备份不变：每日本地 + 每周加密包 + 冷备；SQLite 用 .backup 而不是热拷 .db
④ 客户端版本匹配服务器：MySQL 8.0 的 mysqldump 去 dump 5.7 需要 --column-statistics=0（引擎已处理）
⑤ 日志要看：成功要看数字，不看返回码
```

## 四、性能与容量（给做规划的）

```
单机 SQLite：几万条记忆/消息无压力；单写者，写入排队
MySQL 5.7/8.0：几千到几百万行都行，取决于实例配置（小机器把 innodb_buffer_pool_size 调到 128M~256M）
SQL Server：本项目的基准环境（也是唯一经过长期验证的）
每次命令一次进程启动 + 一次连接：几十毫秒级；每秒几十次的批量场景请直接写库或走常驻连接
```

## 五、还没验证的（诚实列表）

```
· MySQL / SQLite 的长期运行（数周连续无人工干预）← 最重要的一条
· embed 真实嵌入（需要模型端点）
· MySQL 5.6.x / MariaDB / MySQL 8.4+
· 多实例并发写同一个 MySQL（只测了单机顺序调用）
```

## 六、小机器（2 核 4G）怎么配

```
· 2 核 4G 足够跑 SQLite 后端与测试用 MySQL
· 同机还跑 Web/PHP 时，把 MySQL 的 innodb_buffer_pool_size 降到 128M~256M
· 不要同时起两个 MySQL 实例去抢内存（本项目不需要）
```
